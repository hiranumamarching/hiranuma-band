# 運営支援アプリ：利用準備

この段階の実装対象は `admin.html`、`teacher.html`、`parent.html` です。本番の詳細編集と個人カードの自動生成は次のステップで追加します。

## 新規セットアップ

1. アプリ専用のGASプロジェクトに `gas/setup.gs` と `gas/Code.gs` を貼り付けます。既存の器材スプレッドシートを接続しないでください。
2. GASのタイムゾーンを `Asia/Tokyo` に設定します。
3. `setupBandDatabase()` を一度実行します。新規のアプリ専用スプレッドシート、タブ、ダミー名簿を作ります。スクリプトプロパティの `SPREADSHEET_ID` と `ADMIN_TOKEN` が設定されます。
4. GASをウェブアプリとして、自分として実行・利用者がGoogleログインなしでアクセスできる設定でデプロイします。API側では全リクエストに招待トークンを要求します。
5. 管理者は `admin.html?a=<管理者トークン>` を開き、先生は `teacher.html?t=<先生トークン>`、保護者は `parent.html?k=<家庭トークン>` を開きます。初回にGAS Web Appの `/exec` URLを設定します。以後、URLとトークンは端末のlocalStorageに保存されます。トークンは読み込み時にアドレス欄から除去します。
6. 管理者トークンはスクリプトプロパティで確認してください。実トークン、名簿、連絡先、スプレッドシートIDはこのリポジトリに保存しません。API接続先は `api.js` の `defaultEndpoint` にGAS Web App URLだけを設定することもできます。

共有端末では「この端末の認証を解除」を使います。localStorageが使えない端末では招待URLを毎回使ってください。

## 既存DBの午前・午後別スキーマへの移行

既存のアプリ専用GASプロジェクトでのみ実行してください。

1. 新しい `setup.gs` と `Code.gs` に差し替えます。
2. GASエディタから `migrateSessionsSchema()` を実行します。
3. 更新したバージョンでウェブアプリを再デプロイします。管理画面を再読み込みし、午前・午後の設定を確認します。

新規DBの `sessions` は `実施有無_am / staffing_am / 担当先生ID_am / 実施有無_pm / staffing_pm / 担当先生ID_pm` の6列を使います。旧DBでは旧列と既存行を残し、足りない6列を末尾に追加し、同一予定IDの移行行を追記します。旧staffing・担当先生は午前と午後の両方にコピーします。本番だけは午前側を終日として使用し、午後側を空にします。午前が移行済みの行には再追記しません。旧列は以後のAPIレスポンスには返しません。

`setupBandDatabase()` の再実行でも移行できますが、既存DBではダミーデータ投入を伴わない `migrateSessionsSchema()` を推奨します。この作業のために既存行を手動で削除・上書きする必要はありません。

## 管理画面の操作

- **月設定**：年・月のピルで選択し、土曜日を生成。前月の集合・開始・終了・解散時間を引継ぎできます。
- **先生・予定**：可否ボタンで ○／×／未入力を代理入力。午前・午後の実施有無、指導体制、担当先生は独立し、先生ありの枠は○の先生から1名または2名を選びます。本番は終日1枠です。任意日の追加、候補削除、場所・時間・共有備考、自主練チェックリストを編集できます。場所は平沼小学校を初期表示し、必要な場所だけ追加します。
- **集計・当番**：家庭別の未入力／一部入力／入力済、午前午後の人数、当番可の保護者、家庭別の当番可日数を確認。役割ごとの主担当・副担当を選びます。要確認の保護者は個別確認後に割り当てます。
- **公開確認**：自主練の枠を含む日は、異なる在籍保護者2名以上・鍵の担当・中止判断者・緊急連絡先の4条件が必須。不足を表示して公開ボタンを無効にし、APIでも検証します。施設使用申請済は確認項目として記録し、4条件には追加しません。

変更は上部の「変更を保存」で保存します。公開済み予定の予定・当番・自主練情報を保存すると、その予定を下書きに戻します。下書きの間は共有画面から消え、再公開で反映します。公開タブの共有画面は保存済み・公開済みデータだけを描画します。複数APIの保存はトランザクションではありません。エラーが出たら、成功済みの保存がある可能性に注意し、保存し直すか再読み込みで状態を確認してください。

## 追記履歴と公開当番のAPI

- 予定削除は `sessions.確定状態=削除` の行を追記する論理削除です。これは履歴用の内部状態で、通常の下書き／公開画面には出ません。同じ予定IDの最新行で判定します。
- 当番の同一キーは `予定ID + 役割 + 区分（主／副）` です。別の保護者を選ぶと置き換え行を追記します。`保護者ID` が空の最新行は割当解除です。旧履歴に同じ枠の複数担当がある場合、最後の1名を採用します。
- `parent_bootstrap.dutyAssignments` は、公開予定の全当番を返します。各要素は `予定ID / 役割 / 区分 / 表示名` のみです。保護者ID・家庭ID・連絡先・招待トークン・メモは含めません。
- `attendance` と `dutyOffers` は引き続き自家庭分のみです。共有予定の出席は `attendanceCounts` に人数だけを返します。
- `admin_bootstrap.shared` は同じ公開スナップショットです。`shared.js` の `BandShared.render(container, data, monthId)` は将来の保護者画面でも使用できます。
- 管理画面は `admin_create_month / admin_save_month / admin_save_sessions / admin_delete_session / admin_save_teacher_availability / admin_save_selfpractice / admin_save_duty_assignments / admin_publish_month` を使用します。
- 先生画面は `teacher.html?t=<先生トークン>` で対象月の候補を一括表示し、練習なし・自主練・本番の枠を除いて ○／× を送信します。「未入力に戻す」で誤入力を取り消せます。先生の入力締切は設けず、管理者が予定を確定するまで修正できます。
- 保護者画面は `parent.html?k=<家庭トークン>` で、兄弟姉妹全員の月間出席と、家庭としての当番可否を一括入力します。保護者名の選択は不要です。練習なしの枠は表示も送信もしません。入力画面には下書き予定も表示しますが、共有タブには公開済み予定だけを表示します。
- 読み取りもPOSTのJSON本文でトークンを送信できます。GET互換も維持しています。書き込み・公開の検証と追記、公開データの読み取りは同じスクリプトロックで排他します。

## ローカル検証

リポジトリ直下で次を実行します。Node.js標準機能のみ使用し、アプリのビルド工程やnpm依存はありません。

```sh
TZ=Asia/Tokyo node --test tests/*.test.cjs
node --check app/admin.js
node --check app/api.js
node --check app/shared.js
node --check app/parent.js
```

GAS実環境への接続、再デプロイ後の通信、375pxの実ブラウザー表示は別途確認が必要です。`noindex,nofollow` と `robots.txt` は検索抑止であり、データの認可はGAS側のトークン検証が担当します。
